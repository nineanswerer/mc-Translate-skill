# 案例复盘：Desecrated 1.2.0 汉化及 PCL 导出

本篇是一次具体案例，不是所有整合包的适配器、预设数字、价格或授权。事实优先引用当时的记录和结构化报告；历史状态被后续结果取代时保留原因和证据。最后一项反馈明确否定了“已实测自动启用资源包”，见第 12 节。不得把静态文件正确等同于安装器识别、运行时加载或玩家实际体验正确。

## 1. 请求、权责和时间线

用户希望完整游玩时能理解进度、任务、说明和物品，不希望 Codex 消耗大量 Token 亲自批量翻译：Codex 负责策划、调用、代码、定位、保护格式和验收组织，已有可靠中文优先，批量文本和大规模复核交外部服务。用户明确不使用本地模型；即使电脑已有本地模型软件，也不得自行下载模型或运行该服务。授权过必要的小软件与外部资料，但每个环境仍须遵守其网络和权限规则。

实际实例为 Desecrated 1.2.0、Minecraft 1.20.1、Forge 47.4.20；分享对话中较旧版本不能代替本地实例元数据。先做过方案、资源盘点及 10 条小样；之后用户选择 MiniMax 中国站，首轮 ¥5，上限扩展为包含历史调用的全任务累计 ¥25。曾明确暂停，暂停门禁阻止新调用和部署；后明确恢复，恢复时保留账本、缓存和正在途请求。后续反馈重新迭代而非重置预算。

用户先前尝试了 V1 约半小时并反馈实际问题。后续明确禁止代理操作任何启动器或游戏 GUI、抢焦点、移动鼠标键盘、启动/关闭/重启游戏或杀进程；可进行离线文件修复和只读日志诊断，游戏运行时保留待部署成果。最终界面和游玩验收由用户进行。这是本案例的当前约束，未来任务应按各自授权判断。

## 2. 服务、缓存和费用的因果链

网络出错时先辨别站点、代理与 TLS；不能把国际站 401 当成中国站密钥认证成功，也不能关闭 TLS 验证。第一次 TLS 失败是否计费未知，因此保留保守预留。工具的首次下载曾因连接中断得到残文件：官方长度和 SHA256 不一致，不能执行；后续完整下载验证后才允许使用。这个教训适用于任意二进制下载。

建立稳定去重键、上下文和术语相关 source hash，SQLite 保存翻译、失败与每个请求账本；请求前事务预留，成功按 usage 估算结算，结果未知保守占用。SQLite 活跃状态应使用备份 API，不能只复制主数据库而漏 WAL。批量任务受累计上限和用户暂停双重门禁控制；故障只重试失败/受影响项，保存响应并先回收已付费结果。

R4 首版模板复核产生过“理由说翻译但 text 未变”的结果，试验表被放弃而费用保留。后用明确 find/replace 片段及校验构成有效复核表；先回收并重验已付响应，后来仅对尚失败项小批重试。不能因更换表、模型、阶段、代理或新反馈重置预算。费用最后记录：成功 usage 估算 ¥14.91819，保守占用 ¥16.05444，均为估算不是账单，且包含历史不确定请求；上限 ¥25。新 Skill 不继承本案例预算或余额。

## 3. 资源盘点：英文来源不等于生效来源

原模组 `assets/*/lang`、作者资源包覆盖、KubeJS 的 lang 与脚本、FTB Quests SNBT、Patchouli JSON、FancyMenu、配置 TOML、枪包、GUI 图中文字、Java 硬编码与动态拼接都是不同来源。既有中英语言键要按版本、命名空间、加载次序、选中资源包与优先级求实际生效值；不能只找到同名 en_us/zh_cn 文件就判断画面来源。

CFPA 的 1.18 基础、1.20 Forge 和 Fabric 等资源当时按官方哈希取用；准备报告计入 2507 项社区复用、共 5785 项可靠复用，保护 809 个作者改名键并记录 101 个冲突。候选依照版本、键、占位符和数值一致性过滤，不能把已正确作者名称覆盖回通用翻译。术语由外部服务结合上下文拟定，名称核对覆盖任务、物品、提示和手册，例如 Sanguinite、Panvita 和 Cacofey 跨命名空间统一；代码、作者/玩家署名、品牌和常用技术缩写应保留，不能把所有拉丁字母都判成漏译。

一个通用提取工具初次仅捕获了 41 条 FTB 顶层记录，遗漏嵌套正文；实际需要递归提取 1443 条正文及 20 个奖励展示组件。只靠“工具已执行”不能证明覆盖完整。准备目录当时 32,465 条，去重待译 23,672；后续补充菜单正文及图片标题而变化。曾遇手册目录里的 source_file 不在中间 workspace：从 JAR 索引原文、合并 286 份已有中文手册基底解决，不能把缺失中间文件当成不需要的内容。

## 4. 功能数据、文本结构与校验

该实例 41 个任务文件有 815 quest、1049 task、999 reward、85 个 `{@pagebreak}`；1463 个任务/奖励语言键引用及 762 份手册结构作离线检查。该轮分页报告核对了标记总数，不足以单独证明每一处的精确位置，未来要逐字段校验顺序和位置。数字是这个实例的基线而非通用通过门槛：未来需从原始文件自行统计并比较。SNBT 需要可靠解析并往返，替换显示字段后恢复原文字做结构签名；保留 ID、任务条件、奖励、NBT、配方、顺序和分页。Patchouli 非显示字段、页型、配方与解锁条件恢复比较；FancyMenu 保留实例 ID、锚点、URL、可执行动作与可见性等行为字段。

格式保护包括颜色码、字面百分号、`%s`/printf、位置参数、动态拼接 StringConcat 的占位顺序、反引号代码、KubeJS 资源 ID、链接、控制宏、数字/单位与 DecimalFormat；对自动遮罩后的回填要验证数量和语义。Goety 既有中文的颜色重置码也曾漏掉 `§r` 里的 `r`，需依英文基线修复。格式规则不能单纯按字符出现次数判语义：位置参数、无需定位的 printf、代码和正文顺序有不同语义。

我们曾把 Create 的 `create.flap_display.cycles.alphabet` 中 ASCII 分号译为中文分号，还丢了首位空格；字节码按 ASCII `;` 拆分，结果从原生正确的 26 项变为 1 项。V4 直接恢复原 Create 原生中文字符表且保留首位空格；这是我们制造的功能性错误，不是上游原文缺字。教训是识别并锁定功能表、分隔符、占位文本和技术数据，不是看到英文都翻译。

## 5. 硬编码补丁被启动器还原与桥接

V2 五个 JAR 的显示常量在静态文件检查时确已改变；随后的只读 CurseForge 记录显示启动前验证发现哈希不符并重新下载修复，启动时 JAR 哈希与首次原件一致。因此用户看到英文是启动器还原了这五个受管文件的直接证据，而不是简单说“语言包优先级不够”。日志原文和账号数据不放入 Skill。机制适配优先选择资源包、配置、脚本等可维护层；仅在当前加载器与许可允许、证据指向硬编码且必要时，评估独立运行时桥接，不能将本例 Forge 脚本直接套用其他游戏版本。

本例 `lowcodefml`/Forge coremod 桥接覆盖 71 类、168 条非恒等规则；使用实际 Forge coremods 5.2.4 引擎和 Nashorn 类过滤器，离线逐类执行并验证 188 个显示指令值变化、非显示内容零变化。桥接也必须检查 `mods.toml`、`pack.mcmeta`、coremods 引用、版本/mod ID 唯一、ZIP CRC；我们在 1.3.0 漏掉根 `pack.mcmeta`，1.3.1 补齐并确认其余 payload 相同。旧版一次用户启动出现 65 个不同类命中，后续另一次日志约 66 条加载记录且无旧元数据警告；这说明当次转换有执行，不能证明每段提示都在画面正确显示。

Asgard Shield 额外覆盖 17 个显示条目，材料、能力、弱点与格挡时长需保护玩法 ID 和数值。Animus 法典实际 `i18n=true`/`use_resource_pack=true`，正文渲染器对输入走 `I18n.get`：仅翻译字面 JSON 仍可能找不到对应语言键。方案为 96 个英中 JSON、500 个显示值使用稳定键，并补英文回退、中文值及 I18n 百分号转义；原非文本结构恢复比对。条目数量及具体实现只用于本例，不得视作其他书通用机制。

## 6. 反馈定位、故意未知与歧义

截图中的竖直十字齿轮箱 `create:vertical_gearbox` 下方蓝色斜体 `???` 不是由之前显示板字母表直接造成，也没有证据是字体缺字。汉化前 original-files 与首次 deployment-backup 的 `kubejs/startup_scripts/display/displayNames.js` 完全同哈希；其中 `Platform.mods.create.name = '???'` 且注释有 `CREATE IS NOT REAL`。它改的是模组来源显示名，不是物品注册 ID，该脚本本身没有随章节解锁的条件。原包另有隐藏 Create 物品、移除默认配方、A Secret/高塔途径等线索，支持“有意隐藏或玩梗”的推断；未找到作者本人动机说明、未独立核验官方 ZIP，不能升级为确定动机。

先前直接恢复成“机械动力”虽能消除问号，但揭示了来源；用户后来明确决定改为可读且保留隐藏表达的“未知来源”。不要新增完成章节揭示机制、改变物品隐藏/配方/任务依赖或全局替换其他 `???`。当时还有 5 个原英文即为 `???` 的不同场景，以及模组在随机结果/失败回退使用问号的字节码；它们不能无差别视作乱码。未来处理此类反馈时先确定屏幕、物品 ID、当前包版本、加载日志与作者上下文，再选择语义。

宽泛引用检查曾误报 vanilla Minecraft、NEEPMeat 动态键以及任务奖励 translate JSON；一些隐藏章节旧模组引用确实可疑，但静态发现不证明正常游玩被阻断。应记录并按需向用户索取复现，不能擅自安装大型模组、改任务条件或奖励以“消除假阳性”。

## 7. 保护实例、部署、回滚与恢复

首次备份原件和 SHA256，更新建立安装清单，记录源哈希、安装哈希、是否原已存在、上一清单和新文件。原始首次备份不能被后续版本覆盖。用户游玩后可能改变 options：部署先确认已托管文件未发生未预期修改，对允许更新的用户选项保存变更并合并资源包，不把其他选中包删除；对未知冲突中止。安全写入临时文件、原子替换、逐项核验。旧桥接退役要确认受管且匹配哈希，防止同 mod ID 重复。回滚时先比对当前文件等于安装哈希；用户后续修改不得静默覆盖或删除。

Windows 长路径曾需要扩展路径；Python 依赖安装后出现目录不可读，在适当授权范围内复制到任务目录使用，不能将权限失败伪装为验证成功。每次重建接入后续修复脚本和标志，避免旧导出器恢复已废弃的直接 JAR 修改；记录 `phase`、请求门禁、队列、费用、验证、成果和下一步，恢复时读状态并查在途，不重新运行全部翻译。心跳只在持续工作期间启用，完成/暂停/等待用户时停止或保持安静。

## 8. 日志、性能与时间解释

一次用户启动中 Crash Assistant 比主菜单可操作更早弹窗；旧桥接缺元数据确实存在，但不能由时间相邻断言是致命崩溃原因。游戏后来记录主菜单可操作和退出代码 0；代码 0 同样不能证明整个过程无异常。证据按事实和推论分开记。

另一次日志自进程启动到菜单可操作约 98.9 秒、世界首帧累计 152.4 秒；中间包含用户菜单操作和等待，不可将差值直接说成纯进世界加载时间。报告包含 18,581 条 ERROR 行，其中多数是重复堆栈行，不等同独立故障；332 条掉落缺失提示、162 条 EMI 解析异常标题主要在菜单后，不能当作前 99 秒启动根因。GPU 探针子进程的 `-Xmx256m` 不能当游戏主 JVM；CurseForge 自动作者推荐开启，历史手动 4096 MB 不证明主 JVM 使用该值，作者推荐 9000 MB 也不是性能实测。

性能优化是独立任务；建议基于用户亲测冷/热启动、单变量、峰值和 GC 诊断，且能回退。Quantified 开发采集/线程上限与 SmoothBoot 上限仅为候选，并发上限不等于同时活跃量，调低可能更平稳但更慢；本例没有实际应用，也不宣称节省时间。不要顺手堆性能模组、RAM 或改光影、玩法和掉落。

## 9. PCL 安装包、版权与个人信息

普通汉化 ZIP 只含 overrides 及说明，需要已有原包；PCL 版目标为直接拖入。其根目录是 `manifest.json`、`overrides/`，指定 Minecraft 1.20.1 和 Forge 47.4.20；`files` 空数组是因为 406 个顶层源 JAR 已放在 overrides/mods，避免再次下载同一模组。递归 590 条包含 184 个 `.connector` 生成 JAR/input，不能把它们误认为源模组。作者资源、默认配置、主题、枪包、光影、原许可证和 CFPA Notice 均保留；源模组和社区译文各自许可证继续适用，个人迁移不扩大再分发权限。

排除存档、任务进度、账号和用户名缓存、地图探索、最近世界、个人 EMI 历史、启动器个人配置、日志、崩溃/性能记录、探针 JAR、生成缓存、翻译工具及密钥；按内容及文件名进行去敏检查，不能以“没有明文 token”代表所有隐私已证明不存在。源文件读取前后哈希一致，输出在独立目录，先写 partial 完成 CRC 和所有 payload 哈希后替换；已有成品需匹配上次受管哈希，否则不能覆盖未知文件。

包含 Windows x64 Java 21 完整运行目录、NOTICE 与 legal；PCL 版本目录配置使用其源码和本机版本所支持的 `VersionArgumentJavaV2:2`。不能只凭 manifest 的 javaVersion 字段保证启动器会选用它；其他 PCL 版本兼容性与实际选择需用户验证。Minecraft、Forge 和基础库仍须联网获取；“自带模组”不等于完全离线。静态结构检查不能证明 PCL 真正导入或游戏启动成功。

## 10. 署名与彩蛋

## 11. 验收级别与需用户操作的内容
