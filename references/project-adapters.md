# 项目参数与适配器

先发现事实，再选实现。运行 `project_profile.py INSTANCE --output WORK/profile.json`（输出在实例外）可读取公开元数据、文件类型和顶层 JAR 标记；冲突、未知版本和 Java 需求不能靠任意一个文件猜定。输出含 `implemented / needs_adapter / unsupported` 能力状态；implemented 只说明有代码，不说明整个项目运行兼容。

## 项目配置

使用 `assets/task.example.json`，为每个新项目保存实际路径和版本、源/目标 locale、加载器、交付方式、服务、预算及授权。`en_us → zh_cn` 是便于开始的默认值，可选择 `zh_tw` 或其他 JSON locale；不要照搬之前的术语、署名、Java、内存或模组计数。语言代码必须出现在请求身份中，切换语言/提示/术语时升级相应缓存身份。任务持续期间不换账本规避预算。

## 适配器最小协议

每个格式/加载器/输出适配器声明：ID 和版本；支持的游戏/加载器版本范围及实际测试范围；探测条件；提取字段与 locator；功能字段/占位符锁定；源指纹与上下文；构建方式；验证方法；与其他适配器的依赖；回滚和未知输入处理。输入不匹配时返回 needs_adapter/未处理清单，不静默跳过后称全包完成。

新增适配器流程：选一份去敏源样本 → 确认实际加载/语义 → 在副本实现解析和展示字段定位 → 证明非显示结构不变、格式受保护、可构建和回滚 → 加入失败与成功夹具 → 以明确版本/范围接入项目能力清单。功能指令或结构改动不符合纯汉化范围时先停下裁定。

## 交付选择

用户要覆盖补丁、完整安装包、资源包、服务器配置、某启动器导入格式或其他方式时，只选择相应出口；不默认 PCL，也不把任意目录 ZIP 当安装器格式。现有脚本提供经过审查 staging 的 CurseForge 格式容器；其他出口需实现相应清单、下载来源、许可证、哈希和验收，不因读懂其元数据就宣称支持导出。

## 跨 AI 使用

工作流和脚本可移植；路径分隔符、进程检查、凭据读取、脚本执行、权限、监视和子智能体能力按当前运行环境适配。没有工具的纯聊天 AI 可以使用资料规划，但不能独立执行文件闭环。
