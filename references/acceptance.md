# 验收、反馈与故障定位

提供可执行的简短验收清单，优先既往失败场景，再各抽查开局、中期、后期的任务名称/说明/检测/奖励、常见物品提示、一本手册、一处动态界面和资源包顺序。每项写“从哪里进入、检查什么、怎样算通过”。要求用户记录通过/失败/未检查，未玩到的阶段保持未检查；不能要求逐项重做数百任务。

首次安装核验：用户自己拖入 ZIP，记版本名；启动后进入资源包界面，确认中文包在已选并位于可覆盖译文的其他包上方，完成加载后重新打开确认持久。检查中文物品/任务/手册；如需要验证彩蛋，描述能定位的角标及悬停内容。让用户判断配置和实际资源加载/展示，已有安装实例不要重置其选择。如果没启动或用户不允许代理操作 GUI，就只留待用户。

若资源包未选中，先确认确切安装实例与启动器版本，只读比对该实例的 `options`、默认选项模组对应配置、首次运行 journal 是否存在以及资源重载日志先后；不要只根据截图直接推断具体根因。为新导出包修复默认值后需要新隔离实例首次启动复验，已安装实例的用户选择应保留。

收到截图/反馈，先识别具体界面、文字、位置、物品/任务 ID、运行实例、包/模组版本、预期和复现步骤；用户不清楚时自主读配置、日志或源码再提出最少问题。核对当前补丁是否加载、日志中是否有被启动器还原、资源优先级和运行时语言。截图与日志可能含用户名/UUID、目录、认证参数、服务器或世界资料，只摘必要去敏证据，不上传整个日志或放入成品。

`???`、空白、裸键和英文有多种来源：缺译、错误覆盖、字体缺字、动态显示/隐藏状态、调试用模组来源名、真正的玩法秘密。先找来源和上下文，确认是作者原行为还是汉化变更；合理标记推断。查看源码、日志、资源包、原件哈希及与用户决定，不全局改问号，不编造章节后解锁。更改仅影响范围并回归相邻术语、结构、旧问题；记录失败、修复前后和验收结果。

## 日志与性能

警告不自动等于致命原因；崩溃助手弹窗时刻、主菜单可操作时刻、真正异常及退出码需对齐，exit 0 不证明期间无异常。启动累计时间中可能包含菜单等人操作；不同节点相减不能自动得出纯加载时间。辅助 GPU 探针进程的内存参数不是 Minecraft 主 JVM；ERROR 行可包含重复堆栈，不等于独立故障数。运行时 bridge 命中只证明命中，不证明文本语义或视觉。

性能是独立需求：先获取现有配置、硬件、日志相位和实际主 JVM/内存证据，再给可逆单变量对照，记录冷/热启动与多次结果；未测得增益不能称已优化。不为汉化顺手安装优化模组、修改配方、加 RAM、改画质或驱动。

## 经验回写

每次留失败证据、定位思路、修复前后、受影响范围和验证层级；修复规则后只重跑受影响数据。写明哪些是有条件的机制、哪些仅是推断，记录未核对项与回退路径；为 Skill 自身的改动保留版本/变更记录。用户许可、预算、译名在任务状态里持久化，避免重复询问。
