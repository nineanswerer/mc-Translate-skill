# 外部翻译、缓存与总预算

## 服务与费用

优先使用用户已经配置且授权的服务；确认端点区域、模型与接口、上下文长度、费率、并发/限流、数据处理及本次预算。实时价格和可用性应向官方核实，不能假设历史费率。仅在确有缺失时集中询问服务、预算和授权；密钥放在权限受控的本地环境变量/配置，不放对话、状态、日志、进程参数、子智能体消息或 ZIP。先以少量代表性内容做试译，验证术语、格式和费用，再开展用户授权范围的工作。样本费用也算入累计上限。

账本是本任务唯一真实的支出控制源：记录批准上限、币种、价格依据、服务/模型、任务输入指纹、缓存键、每次尝试状态、最大预留、供应商 usage、已确认估算和未知保守占用。发请求之前以事务锁定账本并预留最坏费用；余额不足就不发。供应商成功后，使用可核对的 usage 与价格结算，差额释放；缺 usage、网络超时、进程崩溃或支付状态未知时保持预留或更保守估算，不当作免费失败。不确定请求先检查本地保存的原始响应或供应商能否查询，再人工决策重试；新尝试必须另行预留。累计上限不随轮次、进程、代理或日期重置，余额不足请用户决定是否追加，未同意不继续。

现金计费可能随输入/输出 token、缓存命中、批次、汇率、税费、最小计费和供应商变化而变化；若服务不能提供可信 upper bound，不承诺硬上限可被精确执行：采用更保守的预留及并发上限，或先停止付费等确认。避免把 usage 估算说成最终账单。

## 内容与缓存

先利用可靠现有翻译，挑选缺口和上下文不一致项；将精确源文字、必要上下文、目标语言、术语表版本、字段类型、提示/规则版本及服务模型作为缓存身份。来源路径与实际目标位置单独映射，允许一项译文被多个确实等义的位置复用；同字不同义不能只按原文字去重。缓存有效译文和原始响应，不写入密钥；检索后仍校验格式和术语。状态分类明确：可重用、已预留、请求中、响应已存、校验通过、需修复、失败、请求结果不明。幂等键和受限重试可减少重复，不能假设所有供应商都实现了服务端幂等。

批次按格式、上下文和 provider 限制切分，定义可回收响应协议，限定并发、失败退避与最大重试。先本地格式修复、回收已付响应，不能为了重试包装格式把内容全部再送一次。格式修复后仍需逐项验证显示值、技术 token 与含义；混合中文宜局部修改未译片段，保护已有中文。新 glossary 裁决后增量复核受影响键，明确是否导致缓存失效。

本技能附带脚本能力与实际命令见 `tooling.md`。提供方适配器是一个需自行配置/审查的边界；它能否可靠报告 usage、端点、价格和服务端幂等，取决于具体提供方，脚本不能代替这项核实。无需付费的盘点和校验应在请求前完成。

大批任务使用 [batch-cli.md](batch-cli.md) 中的可恢复编排器，显式标记待译项、提供完整上下文并按保守规则去重；与单次调用共用同一 SQLite 账本。它支持受控并发、用户暂停、有限的未发送重试、已验证缓存复用；结果只通过结构校验，仍需术语与语义复核。
