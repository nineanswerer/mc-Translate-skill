# Skill 维护与回滚

从实际失败收集去敏证据，判断适配器版本和影响范围，先在工作区修改并测试；只重跑受影响条目，保留用户任务中的账本/缓存。不得把一个包的数字、作者动机或未经证实的原因变成普遍事实。对未知格式新增能力和界限，不静默标为已支持。

修改 Skill 前建立有版本的旧文件快照和哈希；先检查安装路径、权限及其他用户修改，不能覆盖未知变化。在工作副本修复、运行测试与结构校验；必要时独立代理用安全隔离的夹具评估行为。只在用户授权及环境允许范围内安装已验证版本；安装前后逐文件对照哈希并保留变更记录。回滚前核对当前版本哈希，若用户后来编辑过则停下保护其修改。

## 变更记录

- 1.0：从一次 Minecraft Java Forge 任务提炼完整流程、预算/恢复/回滚工具、只读语言盘点、实机资源包故障及独立验收边界；具体外部服务需按当时官方接口和计费配置。未做新的付费请求或操作游戏。


## 可持续积累的单位

将通用流程、可执行适配器、项目配置、翻译缓存和案例证据分层。每次记录 finding、适用版本/加载器/格式、evidence、回归方法和当前结论状态（observed/inferred/confirmed）。跨项目复验之前，只能将个案结论作为受限规则或候选机制，不能升级成普遍事实。经验目录属于用户选择的持久项目工作区，不自动写入公开仓库。

同一项目更新先对比源指纹，重用未变条目和已确认术语，失效受影响缓存；删除/迁移字段要处理 locator 和引用，不盲目沿用旧文件。新项目创建自己的授权和累计账本，不继承案例额度。任何变更后让旧验收失效并重新检查受影响场景。

- 1.1：以项目配置和能力清单组织不同包；增加多来源项目发现、可配置 source/target locale；历史案例下沉；明确未实现出口与未知格式的适配流程，保持旧预算/恢复接口。


使用 `scripts/experience_record.py` 可验证证据哈希并写不可覆盖的项目经验记录，模板见 `assets/experience.example.json`。confirmed 仍须记载回归证据且限定作用范围；脚本不代替独立复现或决定普遍适用性。新的案例默认放项目私有经验库，经过用户授权和去敏审核才发布到 references/cases。
