# 可执行脚本与外部适配器协议

仅依赖 Python 3.11+ 标准库；脚本处理通用显示字符串、预算、缓存和明确指定的 staged 文件，不解析所有 MC 格式；配置好的 HTTPS 适配器可联网发送用户授权的请求，离线测试不联网。技能不携带服务商密钥。命令路径均为示例，脚本位于 `scripts/`，配置模板位于 `assets/`。

1. 独立任务初始化一次：`python translation_ledger.py init --db work/ledger.sqlite --cap 10 --currency CNY`。数字仅演示，金额和币种用任务真实授权替换；已有账本不能用 init 重置上限。如果用户明确批准改变同一任务累计上限，在原账本运行 `set-cap --db work/ledger.sqlite --cap 新上限 --authorization "用户明确授权的时间与范围"`，记录变更而不重置费用或在途预留；若降到现有占用之下，立即停止新预留。命令参数不应写用户身份或秘密。并发调用共享 SQLite 账本；保持账本（含 WAL）及备份私密。
2. 请求 JSON 示例：`{"model":"用户实际选定型号", "prompt_version":"v1", "glossary_version":"v2", "entries":[{"key":"item.example.title","source":"Hello %s","context":"物品名"}]}`。把模型、系统提示词、上下文、术语和结构约束的实际版本写入请求，以保证完全相同的请求才能命中缓存。切勿将密钥、身份信息写入请求。`entries` 支持有顺序的批量项目；一个条目可用 `source` 和 `key` 顶层字段。
3. 创建 adapter JSON：参考 `adapter.example.json`，把 `command` 改成用户已经配置的本地可执行适配器 argv（不能用 shell 字符串或在命令参数放密钥），`provider` 和 `identity` 写服务/地域/模型及适配器、计费规则版本，`currency` 与账本一致。程序通过标准输入接收 `{"protocol":"local-json-v1","request_id":整数,"request":请求对象,"max_cost":"上限","currency":"CNY"}`，输出且仅输出一个 UTF-8 JSON 到 stdout：
   - 成功且费用已知：`{"status":"success","translations":["与输入顺序相同的译文"],"cost":"0.002","usage":{"input_tokens":100,"output_tokens":50}}`。
   - 可以确认在**发送请求前**失败、没有产生费用：`{"status":"not_sent"}`。
   - 已知失败但计费明确：`{"status":"failed_billed","cost":"0.002"}`。
   - 超时、非零退出、JSON 无效、响应丢失或费用未知：驱动标记 uncertain，保留整笔预留并禁止自动重发。stdout 不得包含日志；不持久化 stderr。密钥从适配器自行读取的受限环境变量/本地凭据文件获取，不能放命令行或聊天。
4. `python translate_driver.py --db work/ledger.sqlite --request work/request.json --adapter work/adapter.json --max-cost 0.05`。返回 `translated`、`cached`、`already_in_flight`、`paid_output_needs_review`、`budget_frozen`、`budget_exhausted`、`invalid_output` 或 `uncertain`。预留和查缓存是数据库事务，多个代理共同使用同一账本。请求失败但确认计费时仍入账；输出不通过字段/占位符/数字检查时也入账，保留去敏且限长的响应可回收内容，但不直接缓存，**同请求会被阻止再次发送**。先 `python recover_translation.py show --db work/ledger.sqlite --id 请求号` 查看，再 `python recover_translation.py revalidate --db work/ledger.sqlite --id 请求号 --request work/request.json --adapter work/adapter.json` 离线回收可直接通过的输出；需要轻微修复时用 `--candidates work/repaired.json` 提供与原批次顺序相同的译文数组，再验证入同一缓存，费用不重复计。若确实不能恢复且有必要重试，先执行 `translation_ledger.py retry-invalid --db work/ledger.sqlite --id 请求号 --note "已尝试离线回收及重试原因"` 留证，此操作只允许尝试预留，不改变费用与上限。响应只保留明确的内容、状态、费用及 usage 字段，剔除常见敏感字段与 UUID，截断或极大响应只保留有限片段，不保存 stderr；这不是保证识别所有隐私数据的万能脱敏器，输入本身不得含个人信息。带脱敏/截断标记的结果不能入缓存；超过上限可能无法完整回收。结构校验通过仍需后续语义复核。
5. 必须在调用前核实服务当前价格、输入/输出及隐藏推理 token、平台额外收费、精度、模型和区域，以保守最大输入与输出上限计算 **单次最高成本**，并确保适配器及服务端实际限制保证该上限；仅填写 `enforces_max_cost: true` 不是技术证明。若服务无法给出可靠上界，不应调用。驱动按此先预留；实际费用超过预留或服务报告超出已验证 token 界限时如实记账，冻结新付费请求，但无法倒转已发生的费用。查明并修正价格和上界后，可执行 `translation_ledger.py review-bound --db work/ledger.sqlite --id 请求号 --note "计费与上界复核证据"` 记录证据解除该条冻结；累计上限仍生效，需要更高上限必须有用户明确授权。状态 `uncertain` 不会因超时自动释放。到服务账单核对后用 `translation_ledger.py settle --id ... --cost ...` 记录确认值；只有有证据确认根本未提交，才用 `not-sent --id ... --note 证据` 释放；无证据继续占用。中断后先检查 `status`，不得重置账本或更换数据库逃避预算。
6. `python text_guard.py --file work/check.json`，格式为 `{"key":"...","source":"...","translation":"..."}`；输出被锁定的功能字段、占位符/数值/非定位 printf 顺序/颜色码等警告。此校验是保守启发式，不证明语义正确，也不替代格式解析器；普通显示文本需要上下文裁定，不能翻译未知字段。
7. `python file_tx.py plan --stage work/staged --dest /游戏实例 --state work/transaction-001` 建立不可覆盖的首份备份、目标原/新哈希和计划；检查计划后 `python file_tx.py apply --state work/transaction-001`。规划基线只是执行 plan 当时的当前值，**不能代替部署前与本任务历史首次原件及已安装清单的哈希比对**；调用者必须先单独核实旧清单，识别并保护用户后来改动。执行前会保守阻止本机有任何 Java 进程；不会关闭它们。逐文件临时文件原子替换，支持中断恢复，所有目标必须匹配基线。`python file_tx.py rollback --state work/transaction-001` 在所有目标仍匹配原/安装哈希时恢复首份备份，用户后续修改则整体阻止回滚，不能直接覆盖。工具不会自动退役旧 JAR、识别游戏安装状态、合并用户 options 或承诺多文件全事务原子；这些需单独适配、复核。规划仅把 staged 内每个文件视为待替换，必须先保证只包含经过校验的覆盖文件。

`example_adapter.py` 是离线拒绝发送的协议样例，不能翻译。另提供可直接执行的 `openai_compatible_adapter.py`：兼容用户核实后支持标准 HTTPS Chat Completions、`choices[0].message.content`、`usage.prompt_tokens` 和 `usage.completion_tokens` 的服务。先参考 `http-provider.example.json` 写无密钥配置，再参考 `http-driver.example.json` 将 command 中的 Python、脚本、配置路径换成实际路径；密钥仅放配置指定名称的受限环境变量。请求的 `model` 必须与配置一致。JSON 模式、输出上限字段随实际服务配置，接口和 API 版本、价格、币种、隐藏推理及额外收费须从官方资料验证。`verified_max_prompt_utf8_bytes` 是允许的消息序列化字节数，`verified_max_input_tokens` 必须是该范围内**已验证的最坏输入 token 上限**（包含协议开销），`max_output_tokens` 必须是真正由服务执行的计费输出上限。不能仅凭字节数猜 token 上限，确认不了则保持 `provider_pricing_and_token_bound_verified: false`，它会在发送前返回 not_sent；示例零价格也会被拒绝，除非确实验证免费并显式设置 `verified_free_service: true`。请求的 worst-case 费用超过 max-cost 时不发送；成功返回后按 usage 与配置价格结算。请求开始后任何 HTTP、响应或计费未知异常均留下 uncertain，不自动重试。当前仅用假响应离线测试，没有调用真实服务；非兼容提供商需另写适配器并离线测协议。用户希望节省 Codex token，因此大批内容由用户许可且验证的外部适配器翻译，本 Skill 编排和审计。

驱动不自动重试。对确认 `not_sent` 的暂时故障可在原预算内有限次指数退避；`uncertain` 先核对计费；`paid_output_needs_review` 先离线回收，确实不可恢复且必要时才记录 `retry-invalid` 后重新预留。账本不存在或未初始化时禁止发送、不会自动创建空账本；先确认用户预算后初始化。

`python terminology.py --glossary work/glossary.json --catalog work/reviewed.jsonl` 对照术语表定位候选不一致；样式见 `assets/glossary.example.json`，每行至少含 `id`、`source`、`translation`，已审例外使用 `term_exceptions` 列表。它不修改译文，词形、双关和上下文可能造成误报，需结合语境裁决，不能当语义通过证明。`scripts/task_state.py` 的用法和状态迁移见 [workflow.md](workflow.md)。

`python package_cf.py --stage work/reviewed-overrides --manifest work/manifest.json --out work/new-pack.zip` 将已审查覆盖树制成根 manifest + overrides。它拒绝现有输出、常见个人文件、符号链接和重复路径，逐文件验证前后哈希及 ZIP CRC，部分文件在输出同目录；通过硬链接创建新输出而不覆盖既有文件，目标文件系统不支持硬链接时停止并保留 partial，需检查并使用受支持文件系统。它只检查基础元数据、不检查内嵌 JAR/全部隐私/运行时，不完成自动 PCL 导入和游戏验收。
