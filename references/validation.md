# 验证层级与边界

本仓库采用四层证据：文件/结构验证、安装器识别、运行时加载、玩家实测。前一层不能自动证明后一层；任何测试数量都不能替代真实语义和界面验收。

## 当前工具

预算/缓存、批量暂停/恢复、格式与数字保护、术语、源指纹、冲突回滚、打包防覆盖和状态机均有离线回归。本版 50 项离线测试全部通过（v1.0 为 39 项，新增 11 项）。新增的多来源项目发现、元数据冲突、非英语源和繁体目标语言使用合成夹具测试。HTTPS 适配器使用假响应，未对所有真实供应商验证。`project_profile.py` 只发现配置，不安装加载器或确认运行兼容。

语言盘点只解析配置 locale 的 Java JSON，严格重复键/非法 JSON 会列入 errors；动态、required/fixed priority 和自定义文本仍需具体适配。已有译文保留不等于语义正确。元数据识别支持的格式与导出实现分开维护，见 `assets/capabilities.json`。

## 真实历史证据

此前 Desecrated 的一次只读盘点得到 406 个源 JAR、64123 个候选、9 个动态来源未决及 17 个严格解析例外；这些是单个案例数据，不是其他项目阈值。历史上 PCL 首次运行未自动选中中文包的问题已在新导出配置离线修正，修复后全新安装仍待用户验收；不把旧截图或静态正确称为新版实机通过。详见 [案例](cases/desecrated.md)。

当前没有在多个不同真实整合包上完成跨 AI 的完整实战验收。新增适配器只有明确测试及作用范围后才提高能力声明，不能以 README 的覆盖面代替实现与证据。
