# Minecraft 整合包持续汉化 Skill

面向不同 Minecraft Java 整合包的可扩展本地化工作流与工具。它围绕项目识别、适配器、复用译文、预算/缓存、增量更新和验收运转，不绑定某个整合包、加载器版本、翻译商或启动器。

## 可以用来做什么

- 首次汉化：复用社区/原生中文，按语境补缺口，组织术语、批译、检查和交付。
- 版本维护：比较原件与新包，识别新增/变化/删除，增量更新并复用有效缓存。
- 定向修复：定位任务、物品、菜单、手册、动态提示等具体反馈，不重复处理整包。
- 扩充能力：为新格式、加载器版本、服务或输出方式建立适配器和回归样本，再接入项目。

适合科技、魔法、冒险、任务驱动、轻量生活等不同类型的包；实际处理能力由发现的内容格式和已验证的适配器决定，不能按“包的类型”直接保证效果。

## 支持到哪一步

| 内容 | 当前可执行能力 | 必须继续验证的部分 |
|---|---|---|
| 项目发现 | CurseForge、Modrinth、MultiMC/Prism JSON 元数据与顶层模组线索 | 冲突元数据、实际 Java 和运行加载器 |
| 语言资源 | 可配置源/目标 locale 的 JSON 盘点，JAR/已选文件资源包分层 | 动态包、同层冲突及最终运行优先级 |
| 翻译 | 可配置兼容服务或本地适配命令，预算、缓存、批处理与续跑 | 真实服务接口、价格、usage、语义与上下文 |
| 特殊文字 | SNBT、书籍、脚本、菜单、旧版 .lang、图片和硬编码的适配流程 | 需项目专用解析/构建器，当前不含万能自动解析器 |
| 输出 | 已审查覆盖树的 CurseForge 格式 ZIP、哈希与回滚工具 | 具体启动器兼容、Java、首次启用与游戏验收 |
| 其他输出 | 可按适配协议添加 mrpack、服务器或其他启动器交付 | 未实现的出口不能称已支持 |

Forge、NeoForge、Fabric、Quilt 都是可识别和可选择的项目维度；识别并不等于每个版本都做过运行兼容测试。当前范围是 Java 版；基岩版未支持。

## 安装和调用

需要 Python 3.11+。下载 Release ZIP，或克隆到目标 AI 的技能目录。以 Codex 为例：

```sh
git clone https://github.com/nineanswerer/mc-Translate-skill.git ~/.codex/skills/minecraft-modpack-localization
```

> 使用 `$minecraft-modpack-localization` 处理这个整合包。先识别环境和适配器能力，优先复用译文，确认本项目服务与预算后批量处理，按我的目标格式交付，并组织我完成游戏验收。

其他具备文件与 Python 执行能力的 AI 可读取 [SKILL.md](SKILL.md)；技能发现、权限、监视和子智能体机制需适配其平台。用户无需先有本案例对话记录。模板中的示例不是默认授权，密钥不应提交仓库。
